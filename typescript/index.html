01

a abertura

“Levanta a mão quem já fez deploy na sexta.”

Agora deixa a mão levantada quem descobriu no sábado que user.name era undefined.

Esse erro tem nome, sobrenome e endereço — e uma família inteira de primos. Todos evitáveis antes do código rodar.

02

a tese

TypeScript não é sobre escrever tipos.
É sobre mover o erro de lugar.

no editor, agora
custa 10 segundos
no code review
custa 20 minutos e um comentário passivo-agressivo
em produção
custa Sentry lotado, hotfix, e o seu sábado

TypeScript desloca o erro pro lugar mais barato possível: o sublinhado vermelho, antes do commit.

03

exemplo ao vivo

JavaScript aceita tudo

O JavaScript não reclamou. Ele cooperou com o bug.

100 * undefined é NaN — e NaN viaja feliz pelo sistema até aparecer num boleto.

JS discount.js 
function calculateDiscount(order) {
  return order.total * order.discount;
}

// Três meses depois, outro dev chama:
calculateDiscount({ total: 100, discountPercent: 0.1 });

// Resultado: NaN. Sem erro. Sem aviso.
// Só NaN no carrinho do cliente.
04

o mesmo código

TypeScript reclama agora

O erro aparece no editor, com sugestão de correção — antes de virar commit, antes de virar boleto.

“O vermelho no editor é irritante.
O vermelho no Sentry é caro.”
TS discount.ts 
interface Order {
  total: number;
  discount: number;
}

function calculateDiscount(order: Order) {
  return order.total * order.discount;
}

calculateDiscount({ total: 100, discountPercent: 0.1 });
✕
'discountPercent' does not exist in type 'Order'.
Did you mean 'discount'?
05

desmontando as objeções

“Tá, mas…”

“TS me deixa mais lento”

Verdade. Você perde 10 segundos escrevendo o tipo. Em troca, deixa de perder 2 horas debugando por que NaN apareceu num boleto.

É o pior trade da história… pra quem gosta de debugar.

“TS é verboso”

Isso era verdade em 2016. TypeScript moderno infere quase tudo:

const users = ["Ana", "Bruno"];
// ↑ TS já sabe: string[]

const total = users.length * 2;
// ↑ TS já sabe: number

users.map(u => u.toUpperCase());
// autocomplete, zero anotação

Zero anotações. 100% tipado.

“Quando dá problema eu uso any”

any é o TypeScript em modo avião. Tá instalado, tá bonito no package.json, mas não faz absolutamente nada.

Cada any é uma promessa: “confia, eu sei o que tô fazendo”. Daqui a 6 meses, quem lê essa promessa é você.
